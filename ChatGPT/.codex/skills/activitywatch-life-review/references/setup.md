# Set up ActivityWatch review on Windows

Bare invocation checks this computer and the authorized daily review; it does not review habits or install tracking software silently. Resolve Codex home from `CODEX_HOME`, otherwise the current user's `.codex`. No saved username, host, schedule ID, or other computer's local paths are installation defaults.

## Local availability

Use the skill's in-app-browser discovery procedure. Inspect only enough UI to establish the local host and availability of Window, Browser, and Timeline. In Raw Data, if needed, inspect bucket names/watcher metadata only, without opening raw event records. Record missing evidence as unknown: an empty new installation is not broken, but a Browser view alone does not prove its watcher is collecting.

Window and AFK collection come from ActivityWatch's local watchers; detailed browser collection needs its browser extension. If the server, a watcher, extension permission, or the Browser plugin is missing, state the precise pending local step. Provide the [official Windows installation guide](https://docs.activitywatch.net/en/latest/getting-started.html) or [watcher guidance](https://docs.activitywatch.net/en/latest/watchers.html). Do not download/install/start external software, enable autostart, grant tracking permissions, or change ActivityWatch settings just to pass this check. Do so only for a separately authorized installation/repair request through supported tools. No history is restored by installing this skill. Never import or upload history during setup.

## One daily review

1. Discover the native `automation_update` schema. Inspect current Codex-home automation metadata for this skill or the name **Daily ActivityWatch Review**, then confirm candidate IDs through native view. Use accessible Scheduled/app evidence when available. Match by purpose, execution host/destination and local data stream, not display name alone.
2. The user authorizes the current computer as the default daily scheduler during bare/setup invocation. Do not ask which computer should own the daily review, repeat that confirmation, or block setup because account-wide/other-device schedule listing is unavailable. This preference does not establish that another computer's job stopped: leave remote jobs unchanged and report any actually observed overlap briefly. An explicit user choice of another scheduler takes precedence.
3. Reuse a matching local task, including PAUSED status, recurrence/timezone, model, reasoning, destination, notification policy, and unrelated fields. Do not resume, delete, replace, or migrate a task without that request. If several actual local candidates remain indistinguishable, preserve them and report their IDs as a concrete conflict instead of creating another task or asking the generic computer-ownership question.
4. If no matching local task exists, create one standalone local daily task at **20:00 Asia/Singapore** without an additional ownership confirmation. Use local/projectless execution when supported; otherwise discover a suitable non-Git project through native tools. Never create a worktree or manually write automation TOML. Use the current account's available model; prefer the user's `gpt-6.1-sol` preference if available. No speed control means Normal speed cannot be set or verified; do not change global settings.
5. Verify saved ID, destination/host, status, next-run timezone/time, and notifications through native view or Scheduled. Do not create a second task when a call times out: re-inspect before retrying. If the scheduler cannot express the intended timezone, report it; do not quietly schedule 20:00 in a different timezone. Repeating bare invocation must reuse the same verified ID. Keep the computer on and desktop app running for local jobs.

For a newly created task, use a prompt with no machine-specific route:

> Run $activitywatch-life-review in review mode. Keep this run's title Daily ActivityWatch Review. Use Asia/Singapore to choose yesterday and the seven calendar dates ending today, including today through run time; verify the UI's displayed boundaries. Discover this computer's ActivityWatch host through the ChatGPT in-app browser. Read Window, Browser and Timeline for both periods and expand each relevant list as the skill directs. Give the established daily/recent-week observations and practical advice. If access or history is missing, report it accurately. Never substitute another browser, direct API/database access, a fixed calendar week, or a worktree. Do not create schedules during this run.

Preserve an existing task's notification preference. For a new task, retain the user's requested daily review delivery; reserve silence for unchanged non-actionable setup checks, not the requested daily report. Setup ends with a concise checklist of collection availability, discovered local host, schedule ownership/time/status, and any installation/permission/data gaps. Report partial readiness when a watcher or schedule remains unresolved.
